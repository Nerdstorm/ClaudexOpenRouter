# Project guidance

- This gateway is standalone. Do not import another application's code or embed application-specific prompts.
- Use the documented Sign in with ChatGPT public-client flow and public Responses API. Never read desktop/browser credentials or call private ChatGPT backend endpoints.
- The optional `codex/imagegen` backend uses the native Codex CLI boundary with its own ChatGPT login, never extracted credentials or the public plan token. It exposes only the default image engine, never claims a pinned engine/snapshot, and has no paid API fallback. Preserve explicit parameter rejection, shared plus image concurrency, bounded process cancellation, current-thread artifact validation/cleanup and metadata-only usage. Keep model discovery, capabilities and README consistent; image availability is not proof of entitlement.
- Claude uses the official Anthropic API with an explicitly configured API key, behind the same OpenRouter-compatible Chat interface. Keep vendor integration out of client applications. Included Claude credits and any purchased balance are controlled by Claude Console; never claim to verify a credit balance or change billing routes automatically.
- The optional Claude Code subscription backend is explicitly selected at `/claude-code/v1`; existing `/v1` and `/api/v1` Claude calls remain API-key calls. Use native `auth login --claudeai`, safe mode, empty settings/tools/MCP, clean environment and fresh ephemeral sessions. Never extract native credentials or silently fall back to the API. Require native subscription auth, exact model evidence, one completed answer turn and local schema validation. Disclose the one-user-message/nonstreaming subset and CLI-managed caching; reject history and API cache controls rather than silently changing them. Native account extra-usage controls govern possible charges, not API-key removal. Preserve nested plus shared concurrency and cancellation cleanup.
- Preserve caller cache markers and prompt ordering. The optional system-cache default may mark only the end of leading system/developer context, never infer boundaries inside application text. Preserve original JSON schemas for local validation when using Anthropic's documented schema transformation.
- Claude structured output defaults to native grammar enforcement. The operator may explicitly choose `validated_json` for large schemas: append the original schema as a separate formatting block, preserve caller blocks and property order, and validate every completed answer against the original schema. Disclose the mode in capabilities, response headers and journal metadata; never silently switch modes or retry a failed inference.
- Put validated-JSON format instructions in a separate system block after caller system context, preserving caller cache markers. Disclose the instruction version. A completed invalid Claude answer is HTTP 422 with bounded validation paths/rules and usage, so the caller can make an explicit corrected request. Never echo instance values, full schemas or answers in diagnostic errors or logs, and never retry that error inside the gateway.
- Keep account identity, issued client ID and token set together. Validate OAuth state, PKCE, signed identity and granted plan scopes. Refresh rotating credentials serially and write them atomically with owner-only permissions.
- Never log credentials, authorization URLs, prompts, response bodies or schema contents. The request journal records identifiers, hashes, settings, status and usage only.
- Preserve exact model selection and fail explicitly on unsupported parameters, missing grants, exhausted limits and interrupted streams. Do not add model or billing fallbacks.
- Keep configuration, credential storage, OAuth, protocol translation and upstream transport separate and test their boundaries.
- The server binds to loopback by default and requires its own local bearer key. Authenticate management actions too. OAuth callback access logs must remain disabled.
- Keep UI presentation in external stylesheets if a UI is added; no inline styles or CSS-in-JS.
- Run `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest` after changes. Update README and compatibility documentation alongside protocol changes.
- Use Workstate first for project lookup and prior decisions; record useful outcomes when recording is enabled. Use repo name `chatgpt-plan-gateway` for ledger entries. Follow the user's current Workstate guidance.
